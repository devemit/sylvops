# Reviewing local changes

Changes belongs to the selected Checkout (Worktree), including every Session working in it. It does not attribute edits to one agent or compare committed branch history with main.

Desktop and TUI list files in Unstaged, Staged, and Untracked groups. Unstaged compares the working directory with the index; Staged compares the index with HEAD, or the empty tree before a first commit. A partially staged file appears in both groups with a different comparison. Ignored files are excluded. Renames retain the original path. Filtering matches relative file paths without changing Git state.

Select a file to load its numbered diff. Desktop supports Unified and Split views; Split falls back to Unified below 1,000 pixels of diff-pane width. Below 800 pixels of Changes width, Files and file details use separate screens. Drag the file-list divider or use Narrower/Wider to resize it. Split keeps both sides visible; its Horizontal control pans the code on both sides together without moving the line-number gutters. Unified has ordinary horizontal scrolling. Drag across desktop diff rows to select whole lines, then use Copy selection; without a selection, Copy diff copies the loaded patch. Copy path copies the repository-relative path. Copying never includes line-number gutters.

Both clients provide syntax colors for common source/configuration formats, diff-text search with matching-line counts, and previous/next hunk navigation. Search covers the loaded file only. Unsupported languages use plain text; syntax colors are a reading aid, not a parser or verification of code correctness. Long or token-heavy lines may use plain text to bound highlighting work.

Changes refreshes every two seconds while visible. Selection and the nearest logical line are retained as files change. Updated indicates replaced content. Pause freezes the displayed review, including responses already in flight. Refresh now loads one fresh review while remaining paused; Resume restores automatic refresh. Hidden views do not poll. Transient failures preserve the last successful contents with a Stale label and retry control.

The TUI uses a file list beside the diff at 100 columns of available Changes width; smaller views switch between the list and details. Tab switches file/diff focus, Enter opens a file, and Escape returns toward Files and the Navigator. Arrows/j/k and page keys move through the focused pane; left/right scroll code horizontally. `f` edits the path filter, `F` edits diff search, Enter/Escape finish editing, `[`/`]` navigate hunks, `n`/`N` navigate search matches, `p` pauses/resumes, and `R` refreshes. `/` retains the global command palette. Group headers and bottom actions are clickable.

Binary files, symlinks, submodules, special files, unsupported encodings, and unresolved conflicts show explanatory metadata instead of decoded content. Large results are visibly incomplete: status capture is capped at 4 MiB, the file list at 2,000 entries and a bounded path budget, and a selected diff at 256 KiB, 4,000 lines, and 8 KiB per displayed line. One large file does not hide the other listed files. A truncated result is never called clean.

Review is read-only: it does not stage, unstage, discard, commit, push, open an editor, or run repository commands. All Git and file reads belong to the daemon, use validated relative identities, and retain bounded output and timeouts. The CLI's existing checkout-wide diff remains available. Protocol 1.34 requires restarting daemon and clients together after upgrading from 1.33; no database migration is needed.
